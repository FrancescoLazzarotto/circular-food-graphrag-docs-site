    Generare una suite di domande¶

    Quando serve¶

    Per avere in pochi minuti un insieme di domande generate dal modello sui documenti di un'esecuzione della pipeline del grafo, da usare per prove rapide, per dimensionare un run o per la Matrice di retrieval.

    Non è un gold set

    Nessuna domanda generata è verificata sulle fonti, e nessun numero riportato viene da una suite generata (COMMANDS.md, sezione 9). Per le misure si usano i gold set di evaluation/gold/.

    Cosa fa¶

    Il modello legge i pezzi di testo (chunk) di ogni documento e scrive domande di cinque tipi (docstring, generate_questions.py:1-12), con un obiettivo di 25 domande in totale (TARGET_COUNTS, :48-54):

    tipo cosa chiede obiettivo
    fact_based un fatto 7
    multi_hop un collegamento in più passaggi 5
    comparative un confronto 4
    aggregation un'aggregazione 4
    cross_doc qualcosa che richiede più documenti 5

    Per ognuna, se non si chiede il contrario, scrive anche una risposta attesa (ground truth). Vengono scartate le domande sui metadati, con entità segnaposto, quasi duplicate o che contengono già la risposta; con la risposta attesa attiva, anche quelle la cui risposta è un rifiuto o non nomina nessuna delle entità attese (docstring, :5-8).

    Cosa tocca¶

    risorsa effetto
    modelli il generatore indicato da VLLM_BASE_URL e VLLM_MODEL_NAME, lette solo dall'ambiente (:360-371)
    disco legge stage0_documents.json e stage1_chunks.json di un'esecuzione della pipeline (:313-329); scrive un JSON (default artifacts/tmp/graphrag_test_suite.json, :44)
    grafo nessuno
    tempo non misurato; ogni chiamata al modello ha un timeout di 900 secondi (VLLM_HTTP_TIMEOUT, :413)

    Passi¶

    cd /srv/projects/graphllm/experiments/graphRAGPipelineExp1
export VLLM_BASE_URL=http://localhost:8001/v1 VLLM_MODEL_NAME=RedHatAI/Qwen3.8-27B-INT4

    VLLM_MODEL_NAME è obbligatoria: senza, lo script si ferma con Missing VLLM_MODEL_NAME environment variable (:369-370). VLLM_BASE_URL di default è :8000 (:366).

    I comandi vanno lanciati dalla radice della repo con l'ambiente graphllm attivo (vedi Ambiente Python).

    # dall'esecuzione più recente della pipeline
python scripts/gold/generate_questions.py generate

# da un'esecuzione precisa, in inglese, con una copia in testo semplice per la matrice
python scripts/gold/generate_questions.py generate \
  --run-dir kg_pipeline/artifacts/run_<tag> \
  --question-language en \
  --output artifacts/tmp/graphrag_test_suite.json \
  --matrix-output artifacts/tmp/graphrag_test_suite_questions.txt

# un solo documento
python scripts/gold/generate_questions.py generate \
  --doc my_document.pdf --output artifacts/tmp/suite_doc.json

    Eseguito il terzo comando, su A Review of Principal Measuring Tools.pdf con --run-dir kg_pipeline/artifacts/run_full_circular_20260707 e uscita in una cartella temporanea: uscita 0 in 232 s, 18 domande nel file; nel log, 4 domande scartate perché senza fondamento nel testo e 1 perché conteneva la risposta. Non eseguiti i primi due.

    opzione default effetto ancora
    --run-dir l'esecuzione run_* modificata più di recente in kg_pipeline/artifacts da quale esecuzione leggere :297-310, 1560
    --doc tutti un solo documento, per nome del file o doc_id :331-357
    --output artifacts/tmp/graphrag_test_suite.json dove scrivere il JSON :1562
    --question-language en en o it :125-128, 1563-1568
    --matrix-output nessuno scrive anche un file di testo, una domanda per riga :1569-1573
    --matrix-max-questions 0 (tutte) limite per quel file :1574-1579
    --no-ground-truth spento non genera le risposte attese :1580
    --verbose spento stampa ogni domanda accettata :1581

    Come capire che ha funzionato¶

    Lo script stampa saved=<percorso> e, con --matrix-output, matrix_saved=… e matrix_questions=<n> (:1622-1632). Per controllare il contenuto:

    python scripts/gold/generate_questions.py stats --input artifacts/tmp/graphrag_test_suite.json

    stats si ferma con ValueError: <file> has no 'questions' list: not a suite written by 'generate' se il JSON non ha la lista questions, per esempio se si dà un gold set o un rapporto di qualità del grafo (:1525-1526). --allow-missing-questions (:1585-1589) ripristina la stampa di tutti zeri per quel file. Eseguito con conda run -n graphllm su artifacts/tmp/kg_quality_report_local.json: errore col messaggio sopra senza l'opzione, total_questions=0 con l'opzione.

    Output sulla suite esistente in artifacts/tmp/graphrag_test_suite.json:

    total_questions=23
fact_based=7
multi_hop=4
comparative=3
aggregation=4
cross_doc=5
docs_covered=9
model=Qwen/Qwen2.5-32B-Instruct-AWQ
generated_at=2026-06-12T15:35:26.426703+00:00

    23 domande invece di 25: la suite di esempio non raggiunge l'obiettivo; i tipi mancanti sono registrati nei metadati (missing_after_refill, :1499). Il JSON ha metadata (con by_type, docs_used, generation_failures, missing_after_refill, model, question_language, source_run_dir, target_counts, …) e questions, ognuna con id, type, question, ground_truth, expected_entities, source_doc, source_docs.

    Se qualcosa va storto¶

    sintomo causa rimedio
    Missing VLLM_MODEL_NAME environment variable variabile non esportata export VLLM_MODEL_NAME=…
    errore di connessione a :8000 VLLM_BASE_URL non esportata export VLLM_BASE_URL=http://localhost:8001/v1
    Run root not found: kg_pipeline/artifacts lanciato fuori dalla radice della repo (:303-304) cd nella repo, o --run-dir assoluto
    No run_* directories found under: … la cartella esiste ma non contiene esecuzioni run_* (:306-308) indicare --run-dir
    Missing documents artifact / Missing chunks artifact l'esecuzione indicata non ha gli stadi 0 e 1 scegliere un'altra esecuzione
    Document '…' not found in … nome di --doc sbagliato il messaggio elenca i nomi disponibili
