    Aggiornare i documenti della demo¶

    Quando serve¶

    Quando nella cartella del corpus si aggiungono, tolgono o sostituiscono documenti e la demo deve poterli cercare come testo. Questo comando non tocca nessun grafo: per mettere i documenti anche nel grafo serve Aggiungere documenti al grafo.

    Il corpus e il registro¶

    • La cartella del corpus usata dall'ultimo aggiornamento è /srv/projects/graphllm/experiments/Pensiero Sistemico e circolare (AGGIORNAMENTO.txt del run), organizzata in sottocartelle: la prima diventa la colonna tema del registro (kg_pipeline/utils/corpus_registry.py:65).
    • Il registro è product/corpus_registry.csv: una riga per file, separatore ;. È il documento che i curatori del corpus correggono a mano. Colonne (corpus_registry.py:59-77):
    colonna significato
    id_documento identificativo stabile del documento, non cambia mai
    percorso percorso del file rispetto alla cartella del corpus
    impronta SHA-256 del contenuto
    tema, sottotema prima cartella del percorso; le cartelle successive
    lingua lingua principale, proposta e poi corretta a mano
    pagine, pagine_senza_testo per i PDF
    doppione_di se il file è una copia: l'id_documento della copia tenuta (i motivi per cui un file è proposto come copia sono sotto)
    genere, priorita compilati dai curatori
    livello 1 = solo testo cercabile, 2 = anche nel grafo
    escluso se lo stadio 0 salta il file
    ocr se lo stadio 0 legge la copia OCR (riconoscimento ottico dei caratteri, Glossario) invece del file
    note testo libero

    Doppioni¶

    build_registry.py propone come doppione, per ogni riga nuova, il file di rango peggiore di una coppia, e lo segna escluso con una nota doppione proposto di … (motivo) (build_registry.py:376-387). Il motivo è uno di quattro, controllati in quest'ordine (build_registry.py:211-233):

    1. copia identica: stessa impronta SHA-256;
    2. stesso testo: stesse parole (di almeno tre lettere) nello stesso ordine, anche se il file è diverso;
    3. <n>% delle pagine si ritrovano: almeno l'80 % delle pagine della copia si ritrova nell'altro file (_COPY_SHARE, build_registry.py:57), dopo un primo filtro sul vocabolario (:60);
    4. <n>% del testo si ritrova, impaginato diversamente: per le copie rimpaginate (altro formato di pagina, altra edizione), che non hanno pagine in comune. Si confrontano le sequenze di 12 parole consecutive (_SEQUENCE_WORDS, :64) ovunque cadano nella pagina; il file è una copia se almeno la metà delle sequenze si ritrova nell'altro (_COPY_SEQUENCES = 0.5, :68), e solo se ne ha almeno 100 (_MIN_SEQUENCES, :70).

    Pagine senza testo leggibile¶

    Una pagina conta come senza testo per ocr_scanned.py se ha meno di 80 caratteri o se più del 20 % dei suoi caratteri visibili è illeggibile (carattere di sostituzione U+FFFD, di controllo, d'uso privato o non assegnato; ocr_scanned.py:37-58). Capita con i PDF il cui font non ha la mappa Unicode: il testo c'è ma sono caratteri di controllo. Per i file con ocr = sì lo script rifà solo quelle pagine con Tesseract e copia invariate le altre (ocr_scanned.py:74-95).

    Lo stesso 20 % vale quando si costruisce l'indice del testo: i passi fatti per più di un quinto di caratteri illeggibili non entrano nell'indice, e un avviso nel log dice quale file ne ha persi e quanti, ricordando di segnare il file per l'OCR (cli.py:49-58, 681-766; l'indice lo costruisce build_text_index.py con le funzioni di graphrag.cli, :34, :110). Quindi un documento con il testo illeggibile si recupera segnando ocr = sì nel registro e rifacendo l'aggiornamento.

    Cosa fa il comando¶

    Quattro passi, ognuno con il suo script (update_corpus.py:1-26, 268-387):

    1. registro: aggiorna il registro dalla cartella (build_registry.py): righe nuove per i file nuovi, documenti segnati come esclusi se il file non c'è più;
    2. OCR: fa le copie OCR dei PDF scansionati nuovi (ocr_scanned.py);
    3. lettura (stadio 0): legge i documenti inclusi con la pipeline del grafo fermata al primo stadio, kg_pipeline.main --stage ingestion, con un indirizzo del grafo che non risponde (bolt://127.0.0.1:1), così un errore non può scrivere in nessun grafo (:58-60, 309-336);
    4. indice del testo: calcola i vettori dei passi nuovi e controlla che ogni documento incluso abbia passi (build_text_index.py, rapporto in copertura.json).

    Proprietà che contano:

    • Lavora su una copia in kg_pipeline/artifacts/<run>.nuovo, con la propria copia del registro; il run della demo e il registro vengono sostituiti solo se tutti i passi riescono (:10-14, 385-389). Un errore lascia la demo com'era e lo dice: la demo legge ancora … e il registro non è cambiato.
    • Non toglie documenti senza permesso. Se dei documenti oggi inclusi uscirebbero dalla demo (file spariti dalla cartella), si ferma e li elenca, perché con una cartella sbagliata o non montata i file risultano mancanti allo stesso modo (docstring, :13-14); per toglierli davvero serve --allow-removals (:282-295).
    • Rilegge solo il nuovo. Letture e vettori sono in cache per contenuto: solo i file nuovi vengono letti e solo i passi nuovi codificati (:15-17).
    • Un aggiornamento alla volta per run (lucchetto <run>.lock, :167-185); se il registro viene modificato a mano durante l'aggiornamento, non viene sovrascritto (:358-363).
    • Tocca solo cartelle che ha creato lui (file AGGIORNAMENTO.txt dentro, :53-56, 137-150).

    Cosa tocca¶

    risorsa effetto
    grafo nessuno
    GPU nessuna di default: i vettori si calcolano sulla CPU; --gpu 1 li calcola sulla GPU 1 (:436-441, applicato a :255)
    disco kg_pipeline/artifacts/run_corpus_demo/, la cache dei vettori artifacts/vector_index/, la cache delle letture, le copie OCR in kg_pipeline/artifacts/corpus_ocr/; riscrive product/corpus_registry.csv
    tempo ultimo aggiornamento (un documento letto e 171 dalla cache): indice ricostruito in 14,8 secondi (build_seconds in copertura.json); con più documenti nuovi dipende da quanti

    Passi¶

    cd /srv/projects/graphllm/experiments/graphRAGPipelineExp1
PYTHONNOUSERSITE=1 python scripts/corpus/update_corpus.py \
  --corpus-dir "/srv/projects/graphllm/experiments/Pensiero Sistemico e circolare"
# oppure, per calcolare i vettori sulla GPU 1:
PYTHONNOUSERSITE=1 python scripts/corpus/update_corpus.py \
  --corpus-dir "/srv/projects/graphllm/experiments/Pensiero Sistemico e circolare" --gpu 1

    Eseguito in un recinto: registro, cache dello stadio 0, cartella OCR e cache dei vettori copiati in una cartella temporanea e passati con --registry, --stage0-cache, --ocr-dir, --vector-index-dir; --run run_corpus_prova_20261020. Uscita 0 in 235 s: 173 documenti su 173 dalla cache, 0 righe nuove nel registro, 0 documenti usciti; registro invariato (stessa impronta sha256) e stage0_documents.json identico byte per byte a quello di run_corpus_demo. Run di prova cancellato dopo il controllo. Non eseguito sul registro vero.

    opzione default effetto
    --corpus-dir obbligatoria la cartella del corpus
    --registry product/corpus_registry.csv il registro
    --run run_corpus_demo la cartella del run in kg_pipeline/artifacts che la demo legge (DEMO_FULL_CORPUS_RUNS; solo lettere, cifre, _ e -)
    --ocr-dir kg_pipeline/artifacts/corpus_ocr dove stanno le copie OCR
    --stage0-cache dalla configurazione della pipeline (paths.stage0_cache) cache delle letture
    --vector-index-dir artifacts/vector_index cache dei vettori dei passi, quella che legge la demo
    --pipeline-config kg_pipeline/config.yaml configurazione di base dello stadio 0
    --gpu nessuna (CPU) GPU per i vettori
    --allow-removals spento permette ai documenti spariti di uscire dalla demo

    Come capire che ha funzionato¶

    Il comando finisce con un riepilogo e Fatto. (:390-404). Lo stesso riepilogo resta in kg_pipeline/artifacts/run_corpus_demo/AGGIORNAMENTO.txt; quello dell'ultimo aggiornamento:

cartella del corpus: /srv/projects/graphllm/experiments/Pensiero Sistemico e circolare
registro: /srv/projects/graphllm/experiments/graphRAGPipelineExp1/product/corpus_registry.csv
documenti inclusi: 172; letti ora: 1; dalla cache: 171 di 172
righe nuove nel registro: 0
documenti usciti dalla demo: 0

    E copertura.json dello stesso run: 30.906 passi, 172 documenti indicizzati, 0 documenti del registro senza passi, 0 passi di documenti fuori registro, modello intfloat/multilingual-e5-base.

    Dopo, controllare nel registro le righe nuove (genere, livello, priorità, escluso): il comando le propone, le decisioni sono dei curatori (:398-400).

    Farlo vedere alla demo¶

    La demo ha due collezioni di documenti (product/config.py:214-236):

    • tutto il corpus (full), letta da DEMO_FULL_CORPUS_RUNS (default run_corpus_demo) con il registro DEMO_FULL_CORPUS_REGISTRY (default product/corpus_registry.csv). Compare solo se quel run esiste e contiene altro;
    • i documenti del grafo (base), letta da DEMO_TEXT_STAGE0_RUNS (default run_fix2docs_20260710,run_full_circular_20260707, 22 documenti: 20 del primo run e 2 del secondo) e, se impostato, filtrata da DEMO_CORPUS_REGISTRY (default vuoto).

    Chi apre la pagina parte dalla collezione di DEMO_DEFAULT_COLLECTION, predefinita full (product/config.py:236); se full non è offerta parte da base. Nelle impostazioni avanzate si passa all'altra in ogni momento; il grafo è lo stesso per tutte e due.

    Dopo un aggiornamento con i default, basta riavviare l'interfaccia (vedi Riavviare solo l'interfaccia): la collezione "tutto il corpus" legge il run aggiornato. Il messaggio finale del comando dice di riavviare l'interfaccia della demo; se il run è run_corpus_demo e il registro è product/corpus_registry.csv aggiunge che è la raccolta che la demo cerca già di default. Con un altro run o un altro registro stampa invece la riga DEMO_FULL_CORPUS_REGISTRY=<registro> DEMO_FULL_CORPUS_RUNS=<run> da impostare per far leggere alla demo quei file (:391-401).

    I passi uno alla volta¶

    Per capire un errore. Lanciati a mano scrivono il registro sul posto, senza la copia e lo scambio finale (COMMANDS.md, sezione 3): usare una copia del registro.

    python scripts/corpus/build_registry.py --corpus-dir "<corpus>" --registry <copia del registro> --dry-run
python scripts/corpus/ocr_scanned.py --corpus-dir "<corpus>" --registry <copia del registro>
CUDA_VISIBLE_DEVICES=1 python scripts/corpus/build_text_index.py --stage0-runs <run> \
  --registry <copia del registro> --report coverage.json

    Se qualcosa va storto¶

    sintomo causa rimedio
    Cartella del corpus non trovata percorso sbagliato il percorso va tra virgolette: contiene spazi
    <n> documenti oggi inclusi uscirebbero dalla demo file spariti dalla cartella, o cartella sbagliata controllare la cartella; se i file sono stati tolti apposta, --allow-removals
    Un altro aggiornamento di run_corpus_demo è in corso. lucchetto preso aspettare l'altro aggiornamento
    ERRORE nell'indice o nella copertura un documento incluso non ha passi leggere kg_pipeline/artifacts/run_corpus_demo.nuovo/copertura.json
    Il registro … è stato modificato durante l'aggiornamento qualcuno ha salvato il registro mentre il comando girava rilanciare
