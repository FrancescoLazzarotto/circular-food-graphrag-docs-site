    Servire i modelli¶

    Quando serve¶

    Il progetto non carica i modelli dentro i propri processi: li chiede a server vLLM separati, che parlano lo stesso protocollo delle API di OpenAI (/v1/models, /v1/chat/completions, /v1/embeddings). Servono:

    • un generatore, che scrive le risposte (demo, campagne, giudice);
    • un encoder, che trasforma nomi dei nodi e domande in vettori nello stesso spazio multilingue, così una domanda in inglese trova un concetto scritto solo in italiano (docstring di src/graphrag/embeddings.py:1-8);
    • durante la costruzione del grafo, un estrattore, che legge i pezzi di testo e ne ricava le triple.

    Per la demo completa c'è uno script unico: Avviare e fermare la demo. Questa guida serve quando si vuole un modello alla volta: un esperimento, l'estrazione del grafo, un confronto.

    Cosa tocca¶

    risorsa effetto
    GPU una quota della memoria fissata da --gpu-memory-utilization (tabella sotto), presa all'avvio e tenuta finché il server è acceso
    disco i pesi nella cartella indicata da HF_HOME, di default /mnt/storage/hf-cache (sotto); se mancano, vengono scaricati al primo avvio
    rete ogni server ascolta solo su 127.0.0.1, senza autenticazione (start_vllm_qwen38_27b.sh:29-31)
    tempo caricare un modello da 27-32 miliardi di parametri a cache del disco fredda richiede minuti (commento a start_demo.sh:47)

    Gli script¶

    Tutti in scripts/serving/. Ognuno lancia vllm serve in primo piano con exec: il terminale resta occupato finché il server gira.

    script modello (default) porta GPU memoria GPU note
    start_vllm_encoder.sh intfloat/multilingual-e5-base 8002 1 0.12 --runner pooling (fa vettori, non testo); --max-model-len 512; esce subito con encoder already serving se la porta risponde già (:26-29)
    start_vllm_qwen38_27b.sh RedHatAI/Qwen3.8-27B-INT4, revisione fissata 8001 1 0.90 generatore della demo; template di chat che spegne il "ragionamento"; quota dichiarata nello script come quella che segue la cache KV del compito (:9-10)
    start_vllm_qwen25_7b.sh Qwen/Qwen2.5-7B-Instruct 8001 1 0.87
    start_vllm_qwen3.sh Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 8001 1 0.87
    start_vllm_gemma4_31b.sh google/gemma-4-31B-it-qat-w4a16-ct 8001 1 0.85
    start_vllm_qwen3_32b.sh Qwen/Qwen3-32B-AWQ 8000 0 0.87 l'estrattore del grafo; scheda con VLLM_QWEN3_32B_GPU (:10)
    start_vllm.sh Qwen/Qwen2.5-32B-Instruct-AWQ 8000 0 0.87 --dtype float16; il modello si sceglie con VLLM_MODEL_NAME (:9), la scheda con VLLM_GPU (:11); pesi non in cache
    start_vllm_qwen25_72b.sh Qwen/Qwen2.5-72B-Instruct-AWQ 8000 0,1 0.90 due GPU (--tensor-parallel-size 2); vuole entrambe le schede libere al 90%; pesi non in cache
    start_vllm_qwen38_27b_bf16.sh Qwen/Qwen3.8-27B 8000 0,1 0.88 due GPU; vuole entrambe le schede libere all'88%; pesi non in cache

    Parametri comuni ai generatori: --max-model-len 32768, --max-num-seqs 16, --enable-prefix-caching, --enable-chunked-prefill (per esempio start_vllm_qwen38_27b.sh:33-44). --max-model-len conta: vLLM rifiuta una richiesta quando prompt più token da generare superano quel limite, e l'estrazione chiede fino a 4096 token nuovi (commento a start_vllm.sh:4-5).

    "Pesi in cache" misurato con ls /mnt/storage/hf-cache/hub.

    Le variabili che cambiano uno script¶

    Ogni valore si può cambiare con una variabile d'ambiente, il cui nome dipende dallo script. Le più utili:

    cosa variabili
    GPU EMBED_GPU, VLLM_QWEN38_GPU, VLLM_QWEN25_7B_GPU, VLLM_QWEN3_GPU, VLLM_GEMMA4_GPU, VLLM_QWEN3_32B_GPU, VLLM_GPU (per start_vllm.sh), VLLM_QWEN25_72B_GPUS, VLLM_QWEN38_BF16_GPUS
    porta EMBED_PORT, VLLM_QWEN38_PORT, VLLM_QWEN25_7B_PORT, VLLM_QWEN3_PORT, VLLM_GEMMA4_PORT, VLLM_QWEN3_32B_PORT, VLLM_PORT, VLLM_QWEN25_72B_PORT, VLLM_QWEN38_BF16_PORT
    memoria GPU EMBED_GPU_UTIL, VLLM_QWEN38_UTIL, VLLM_GEMMA4_UTIL, VLLM_QWEN25_72B_UTIL, VLLM_QWEN38_BF16_UTIL (gli altri hanno 0.87 scritto nel comando)
    modello GRAPHRAG_EMBED_MODEL, VLLM_QWEN38_MODEL, VLLM_QWEN25_7B_MODEL, VLLM_QWEN3_MODEL, VLLM_GEMMA4_MODEL, VLLM_QWEN3_32B_MODEL, VLLM_MODEL_NAME, VLLM_QWEN25_72B_MODEL, VLLM_QWEN38_BF16_MODEL
    tutti VLLM_BIN (quale vllm usare), HF_HOME (cache dei pesi), VLLM_HOST (indirizzo; 0.0.0.0 per aprire il server alla rete)

    Dove stanno i pesi: HF_HOME¶

    Ogni script start_vllm*.sh ha una riga export HF_HOME="${HF_HOME:-/mnt/storage/hf-cache}": una HF_HOME già esportata vince, altrimenti vale /mnt/storage/hf-cache. Le righe sono start_vllm.sh:16, start_vllm_encoder.sh:24, start_vllm_gemma4_31b.sh:19, start_vllm_qwen25_72b.sh:17, start_vllm_qwen25_7b.sh:11, start_vllm_qwen38_27b.sh:27, start_vllm_qwen38_27b_bf16.sh:21, start_vllm_qwen3.sh:15, start_vllm_qwen3_32b.sh:18.

    • Cambiare cartella dei pesi vuol dire esportare HF_HOME=<cartella> prima dello script. start_demo.sh non imposta HF_HOME e lancia server e interfaccia ereditando l'ambiente (start_demo.sh:144-146, :206-210): una HF_HOME esportata prima di start_demo.sh arriva a tutti i server che avvia.
    • La colonna "pesi in cache" di Avviare e fermare la demo vale per /mnt/storage/hf-cache. In un'altra cartella un modello che non c'è viene scaricato al primo avvio.
    • Lo stato della cartella predefinita, misurato con ls -ld: drwxrwsr-x+, gruppo llmproject (permessi di scrittura al gruppo); 222 GB con du -sh.

    Avviare un modello¶

    1. Guardare chi occupa le GPU: 
      nvidia-smi
    2. Avviare prima l'encoder, così si prende la sua quota della GPU 1 prima del generatore (COMMANDS.md, sezione 1): 
      cd /srv/projects/graphllm/experiments/graphRAGPipelineExp1
setsid nohup bash scripts/serving/start_vllm_encoder.sh > scripts/serving/logs/encoder.log 2>&1 &
    3. Avviare il generatore, nello stesso modo: 
      setsid nohup bash scripts/serving/start_vllm_qwen38_27b.sh > scripts/serving/logs/qwen38_int4.log 2>&1 &
      setsid nohup … & stacca il server dal terminale, così sopravvive alla chiusura della sessione. La cartella scripts/serving/logs/ è ignorata da git (.gitignore:34) e oggi contiene log scritti così a mano: nessuno script ci scrive da solo.
    4. Aspettare che risponda: 
      curl -s http://localhost:8001/v1/models | python -m json.tool
      Finché carica, curl non risponde. Quando è pronto restituisce un JSON con l'id del modello.

    L'estrattore del grafo chiede l'87% di una scheda: non sta sulla stessa scheda del generatore della demo (90%), vLLM si fermerebbe all'avvio per memoria libera insufficiente (vedi GPU, porte e dischi). Per lanciarlo sulla GPU 1, prima si ferma il generatore:

    bash scripts/serving/stop_demo.sh qwen38-27b
VLLM_QWEN3_32B_GPU=1 setsid nohup bash scripts/serving/start_vllm_qwen3_32b.sh > scripts/serving/logs/qwen3_32b.log 2>&1 &

    Fermare un modello¶

    Un server avviato da start_demo.sh si ferma con stop_demo.sh <etichetta> (vedi la guida della demo). Uno avviato a mano non ha un file di pid:

    ss -ltnp | grep ':8001 '          # quale pid ascolta sulla porta
kill <pid>                        # poi ricontrollare con nvidia-smi che la memoria sia liberata

    Un server vLLM può ignorare SIGTERM mentre carica i pesi (commento a stop_demo.sh:4-7): se dopo 30 secondi è ancora vivo, kill -9 <pid>.

    Scelte che non vanno toccate senza motivo¶

    • La revisione del generatore è fissata. start_vllm_qwen38_27b.sh:12-13,16 usa la revisione 2fb0debc… di RedHatAI/Qwen3.8-27B-INT4: le revisioni successive mettono la cache dell'attenzione in FP8, che le A40 non sanno eseguire, e il risultato è testo senza senso. Togliere la revisione riporta il problema.
    • Il "ragionamento" è spento dal template. I modelli Qwen3 e Qwen3.8 di default scrivono un ragionamento prima della risposta. I template scripts/serving/chat_templates/qwen3_nothink.jinja e qwen38_nothink.jinja lo spengono, a meno che il client lo chieda con chat_template_kwargs {"enable_thinking": true} (commento a start_vllm_qwen38_27b.sh:4-7; qwen38_nothink.jinja:46,165).
    • Encoder e indice devono usare lo stesso modello. L'indice vettoriale del grafo è costruito con i vettori di intfloat/multilingual-e5-base. Cambiare il modello dell'encoder senza ricostruire l'indice degrada il recupero senza errori (start_vllm_encoder.sh:13-15, embeddings.py:6-8). Per ricostruire: scripts/kg/kg_vector_index.py, vedi Ricostruire il grafo.
    • import vllm non funziona in graphllm. Gli script usano l'ambiente vllm-serve tramite VLLM_BIN. Mai conda run -n graphllm vllm (COMMANDS.md, sezione 1).

    Come il codice trova i server¶

    chi variabili default di .env.example
    encoder, per recupero e indice GRAPHRAG_EMBED_BASE_URL, GRAPHRAG_EMBED_MODEL http://localhost:8002/v1, intfloat/multilingual-e5-base
    generatore, con --vllm sulla riga di comando e per il giudice VLLM_BASE_URL, VLLM_MODEL_NAME, VLLM_API_KEY http://localhost:8000/v1, Qwen/Qwen2.5-32B-Instruct

    Attenzione: il default punta alla porta 8000, mentre il generatore della demo sta sulla 8001. Per un esperimento con quel generatore si esportano VLLM_BASE_URL e VLLM_MODEL_NAME, oppure si passano le opzioni del runner: vedi Lanciare una campagna.

    Ricreare l'ambiente vllm-serve¶

    Gli script trovano l'ambiente tramite VLLM_BIN (il percorso dell'eseguibile vllm): un ambiente ricreato altrove si usa esportando quella variabile.

    Il file con l'elenco è env_snapshots/vllm-serve.pip-freeze.txt (176 righe: vLLM 0.19.1, torch 2.10.0, FlashInfer 0.6.6, transformers 5.13.0). Il percorso docs/40_operations/… è relativo alla cartella di questa documentazione.

    Se qualcosa va storto¶

    sintomo causa rimedio
    ModuleNotFoundError: No module named 'vllm' o errori di import lanciato con il vllm di graphllm usare gli script; controllare VLLM_BIN
    errore di memoria CUDA all'avvio GPU già occupata, oppure due modelli grandi insieme sulla GPU 1 nvidia-smi; fermare il modello precedente; ridurre la quota con la variabile …_UTIL
    risposte senza senso da Qwen3.8-27B revisione del modello diversa da quella fissata non esportare VLLM_QWEN38_REVISION
    il server parte ma impiega molti minuti, il log mostra download pesi non in cache attendere; controllare lo spazio con df -h /mnt/storage
    un client riceve 400 su richieste lunghe prompt più token richiesti oltre --max-model-len (32768): vLLM solleva VLLMValidationError (vllm/renderers/params.py:414-424) e la trasforma in 400 Bad Request (vllm/entrypoints/utils.py:318-320, venv vllm-serve) ridurre il contesto o i token richiesti
    start_demo.sh non riesce ad avviare uno script start_vllm*.sh lo script non ha il bit di esecuzione: start_demo.sh lo esegue direttamente (start_demo.sh:146). L'indice di git registra tutti i 433 file tracciati con modo 100644 e nessuno con 100755 (git ls-files -s) e la repo ha core.fileMode=false (git config core.fileMode): git non segnala la differenza di permessi, e uno script riscritto da un checkout resta senza il bit chmod +x scripts/serving/*.sh
    il recupero in inglese peggiora senza errori encoder spento o con un modello diverso da quello dell'indice curl :8002/v1/models; controllare GRAPHRAG_EMBED_MODEL
