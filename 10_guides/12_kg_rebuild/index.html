    Ricostruire il grafo¶

    Quando serve¶

    Per costruire il grafo da zero a partire dai documenti: cambio dell'estrattore, del prompt, della configurazione della pipeline, o un corpus nuovo. Per aggiungere qualche documento a un grafo che esiste già si usano i lotti.

    La ricostruzione si fa sempre sul grafo di staging (porta 7689), mai su quello di produzione; il grafo misurato si porta poi in produzione con Il grafo di produzione.

    Cosa tocca¶

    risorsa effetto
    grafo stadi 0-5: nessuno. Stadio 6 e curatela: scrivono nel grafo indicato dal rebuild.env del run. Il passo 3 della curatela svuota lo staging (replay_curation.sh:63-66)
    GPU estrattore Qwen/Qwen3-32B-AWQ su :8000 (quota 0.87 di una scheda, start_vllm_qwen3_32b.sh); encoder su :8002 per gli indici (passo 12); GLiNER (stadio 2) va sul dispositivo di KG_NER_DEVICE solo se la variabile è impostata (stages/ner.py:48-50); il modello dello stadio 4 su KG_EMBED_DEVICE, e se vuota sentence-transformers sceglie cuda quando c'è una GPU (stages/resolution.py:354-355)
    disco una cartella per run in kg_pipeline/artifacts/run_<etichetta>/ con tutti gli artefatti; il registro di lettura dello stadio 0 in kg_pipeline/artifacts/stage0_cache (config.yaml:6-8)

    Il grafo di riferimento: run E¶

    Il grafo di produzione viene dal run kg_pipeline/artifacts/run_rebuild_20260922_E: il backup del run (artifacts/kg_backups/replay_E_etichette_20260924) e il backup notturno della produzione hanno gli stessi conteggi di nodi e archi, per ogni etichetta e ogni tipo di arco (confronto dei due manifest.json). Quella cartella è il modello da copiare per un run nuovo:

    file cosa contiene
    config.yaml la configurazione della pipeline; rispetto a kg_pipeline/config.yaml differisce in tre righe: niente stage0_cache, percorso assoluto del vocabolario delle relazioni, neo4j.database: 'neo4j' invece di '588fe1bc' (misurato con diff)
    rebuild.env NEO4J_* dello staging bolt://localhost:7689, estrattore http://localhost:8000/v1 con Qwen/Qwen3-32B-AWQ
    run_metadata.json seed 42, commit 4e22954, GLiNER urchade/gliner_multi-v2.1, modello dello stadio 4 sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2; 10 invocazioni
    merge_verdicts.json, bilingual_proposals_round{1,2}.json, bilingual_excluded.json le decisioni dei modelli e delle letture: con questi file la curatela si ripete senza chiamare modelli (replay_curation.sh:14-18)
    stage0_documents.json … stage6_neo4j_summary.json gli artefatti di ogni stadio

    Lo staging (porta 7689)¶

    bash scripts/serving/start_neo4j_staging.sh          # stampa "bolt://localhost:7689 is up"

    Default dello script (start_neo4j_staging.sh:18-22): installazione /mnt/storage/<utente>/neo4j_v2/neo4j-community-5.26.0, Java dall'ambiente conda neo4jrt, Bolt 7689, HTTP 7476, password dalla variabile STAGING_PASSWORD, con un default scritto nello script (:22). Gli script di curatela hanno la stessa password come default (replay_curation.sh:31, bilingual_merges.py, edge_rules.py, drop_nodes.py, kg_densify.py). Per spegnerlo:

    JAVA_HOME=/home/<utente>/.conda/envs/neo4jrt PATH=/home/<utente>/.conda/envs/neo4jrt/bin:$PATH \
  /mnt/storage/<utente>/neo4j_v2/neo4j-community-5.26.0/bin/neo4j stop

    I passi¶

    1. Preparare la cartella del run¶

    RUN=kg_pipeline/artifacts/run_<etichetta>
mkdir -p $RUN
cp kg_pipeline/artifacts/run_rebuild_20260922_E/config.yaml $RUN/
cp kg_pipeline/artifacts/run_rebuild_20260922_E/rebuild.env $RUN/

    rebuild.env deve puntare a bolt://localhost:7689: la curatela si rifiuta di partire altrimenti (replay_curation.sh:39-41). --env-file viene caricato sopra l'ambiente (load_dotenv(..., override=True), main.py:837).

    2. Accendere l'estrattore¶

    VLLM_QWEN3_32B_GPU=1 bash scripts/serving/start_vllm_qwen3_32b.sh

    Chiede l'87% della scheda: sulla GPU 1 non sta insieme al generatore della demo (vedi GPU, porte e dischi).

    3. Stadi 0-5¶

    export PYTHONHASHSEED=42
setsid nohup env PYTHONNOUSERSITE=1 PYTHONHASHSEED=42 python -m kg_pipeline.main \
  --config $RUN/config.yaml --env-file $RUN/rebuild.env --run-dir $RUN --stage linking \
  >> $RUN/rebuild.out 2>&1 < /dev/null &
tail -f $RUN/pipeline.log
    stadio nome per --stage artefatto (main.py:391-406)
    0 lettura dei PDF ingestion stage0_documents.json
    1 frammenti chunking stage1_chunks.json
    2 entità candidate (GLiNER) ner stage2_ner.json
    3 estrazione delle triple (estrattore) llm stage3_triples_raw.json, stage3_acronyms.json, failed_chunks.jsonl
    4 risoluzione delle entità resolution stage4_triples_resolved.json, stage4_registry.json, stage4_merge_approved.json
    5 collegamenti linking stage5_triples_linked.json
    6 scrittura nel grafo neo4j o all stage6_neo4j_summary.json

    Regole del comando:

    • --stage arriva fino a quello stadio compreso, rifacendo o rileggendo tutti i precedenti (main.py:875-922). Non esiste un'opzione per un solo stadio. Il default è all: senza --stage si arriva allo stadio 6 e si scrive nel grafo del --env-file.
    • Ogni artefatto ha un'impronta degli input che l'hanno prodotto, in stage_fingerprints.json. Se un artefatto esiste ma gli input sono cambiati, il run si ferma con <file> was produced from different inputs than this run asks for invece di rifarlo o riusarlo (main.py:350-388). Si cancella quel file e tutti i successivi, o si usa un --run-dir nuovo. Le impostazioni che contano per ogni stadio sono in main.py:412-426; per lo stadio 3 conta anche VLLM_MODEL_NAME (:574-580).
    • PYTHONHASHSEED deve valere quanto seed (42): Python lo legge solo all'avvio; se diverso la pipeline scrive un avviso e prosegue (main.py:57-67). Lo stadio 4 sceglie fra grafie che differiscono solo per maiuscole nell'ordine di un insieme, che dipende da quel valore (replay_curation.sh:33-36).
    • Lo stadio 3 salva un checkpoint ogni llm.checkpoint_every frammenti (50, config.yaml:61) in stage3_checkpoint.json: rilanciare riprende da lì (COMMANDS.md §5). Lo stadio 4 non ha checkpoint.
    • --dry-run si ferma prima dello stadio 6 e stampa cinque triple d'esempio (main.py:924-931). --single-doc <file o id> lavora su un solo documento.

    Frammenti falliti allo stadio 3: sono in failed_chunks.jsonl. Si riprovano prima dello stadio 4:

    python scripts/kg/kg_retry_failed.py --run-dir $RUN --config $RUN/config.yaml --env-file $RUN/rebuild.env

    Opzioni (kg_retry_failed.py): --timeout 400, --max-tokens 8192, --concurrency 8, --max-retries 2.

    4. Curatela: replay_curation.sh¶

    bash scripts/kg/curation/replay_curation.sh $RUN
START_STEP=9 bash scripts/kg/curation/replay_curation.sh $RUN      # riprendere dal passo 9

    Lo script esporta PYTHONNOUSERSITE=1 e PYTHONHASHSEED=42 e lancia Python con conda run -n graphllm (variabile PY) (replay_curation.sh:28-36).

    passo cosa fa script modelli
    1 secondo giudizio, più severo, delle unioni dello stadio 4 curation/rejudge_merges.py estrattore, salvo merge_verdicts.json completo
    2 stadi 4-5 rifatti con le sole unioni confermate kg_pipeline.main --stage linking modello dello stadio 4
    3 svuota lo staging kg_wipe.py --yes —
    4 stadio 6: scrive il grafo kg_pipeline.main —
    5 toglie i nodi alias e li fa diventare aliases kg_collapse_aliases.py --yes —
    6 autoanelli e nodi generici quality/pass1_cleanup.py --apply —
    7 regole sugli archi (AUTHORED_BY rovesciati, HAS_VALUE con numeri non nel testo) curation/edge_rules.py --apply —
    8 nodi anaforici ("il progetto", "l'iniziativa") curation/drop_nodes.py --anaphoric --apply —
    9 unioni bilingui, giro 1: grado ≥ 4, 3 vicini, coseno ≥ 0,87 curation/bilingual_merges.py estrattore, salvo proposte già scritte
    10 unioni bilingui, giro 2: grado ≥ 20, 10 vicini, coseno ≥ 0,85 idem idem
    11 nodi rimasti senza archi curation/drop_nodes.py --isolated --apply —
    12 indici: testo di ricerca, vettori (cancellati e rifatti), controllo kg_search_index.py, kg_vector_index.py --drop, kg_vector_index.py, check_vector_index.py --min-resolving 1000 encoder su :8002

    L'estrattore si cerca su CURATION_ENDPOINTS, default http://localhost:8000/v1,http://localhost:8003/v1 (replay_curation.sh:30).

    I giri bilingui si fermano per la lettura: se bilingual_proposals_round<N>.json non c'è, lo script lo scrive, stampa le istruzioni ed esce con 0 (:93-102). Si leggono le proposte, si scrivono quelle sbagliate in $RUN/bilingual_excluded.json:

    {"escluse": [{"giro": 1, "unito": "<nome>", "centro": "<nome>"}]}

    e si riprende con START_STEP=9 (giro 1) o START_STEP=10 (giro 2).

    5. Dopo la curatela¶

    1. misurare lo staging (vedi Matrice di retrieval e Valutare un run);
    2. fermare lo staging;
    3. portarlo in produzione con load.sh (Il grafo di produzione).

    Rifare solo la risoluzione¶

    Per provare soglie diverse dello stadio 4 senza rifare l'estrazione:

    python scripts/kg/remerge_entities.py --run-dir $RUN \
  --embedding-model sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 \
  --similarity-threshold 0.90 --context-jaccard-floor 0.15

    Altre opzioni: --output-dir (default: una sottocartella remerge_<data_ora> della cartella del run, remerge_entities.py:84-88), --base-url / --model-name / --api-key (default VLLM_BASE_URL, VLLM_MODEL_NAME, VLLM_API_KEY), --exclude-mentioned-in.

    Densificazione (non usata nel grafo di riferimento)¶

    scripts/kg/kg_densify.py aggiunge archi fra entità che il grafo ha già, frammento per frammento. Non fa parte della ricostruzione di riferimento (vedi sopra). Default: staging bolt://localhost:7689, generatore http://localhost:8001/v1 con RedHatAI/Qwen3.8-27B-INT4, --output artifacts/kg_v2/densify.jsonl; senza --chunks-dir legge i frammenti delle cartelle di CHUNK_DIRS, cioè run_full_circular_20260707 e run_fix2docs_20260710 (kg_densify.py:54-57, 421-423, 442). COMMANDS.md §5 avverte: passare sempre --chunks-dir $RUN (il default legge i frammenti di run vecchi) e tenere --output nella cartella del run, perché --apply applica ogni densify*.jsonl accanto.

    Indici, backup, ripristino, svuotamento¶

    python scripts/kg/kg_search_index.py --config $RUN/config.yaml --env-file <env del grafo>
python scripts/kg/kg_vector_index.py                 # vuole l'encoder su :8002
python scripts/kg/kg_vector_index.py --only-missing  # solo i nodi senza vettore
python scripts/kg/check_vector_index.py --min-resolving 1000

python scripts/kg/kg_backup.py --output-dir artifacts/kg_backups/<nome> --include-vectors
python scripts/kg/kg_restore.py --backup-dir <cartella> --uri bolt://localhost:7689 --password <pw> --wipe
python scripts/kg/kg_wipe.py --config $RUN/config.yaml --env-file $RUN/rebuild.env          # solo conta
python scripts/kg/kg_wipe.py --config $RUN/config.yaml --env-file $RUN/rebuild.env --yes    # svuota
    • kg_search_index.py carica il suo --env-file sopra l'ambiente e prende il database da --config (COMMANDS.md §5): con i default della repo (kg_pipeline/.env, kg_pipeline/config.yaml) va sull'istanza ospitata.
    • kg_backup.py legge le NEO4J_* esportate; per quelle che mancano ricade sul .env della radice (load_dotenv(REPO / ".env", override=False), kg_backup.py:108). Senza --output-dir scrive in artifacts/kg_backups/<data> (:111).
    • Un ripristino da JSON (kg_restore.py) cambia gli identificativi dei nodi: i vettori restano scollegati. Dopo: kg_search_index.py, poi kg_vector_index.py --drop, kg_vector_index.py, check_vector_index.py (COMMANDS.md §5). Dopo un caricamento con neo4j-admin si usa invece relink_vectors.py, che load.sh lancia da solo.

    --run-post e i passi dopo lo stadio 6¶

    Alla fine dello stadio 6 la pipeline elenca come NOT RUN i passi che non ha fatto: densificazione, testo di ricerca, indice vettoriale (main.py:724-796; per la densificazione stampa la conseguenza no edges between entities named in the same chunk; needs a served model, :733). Con --run-post lancia i due indici; la densificazione non la lancia mai. La ricostruzione con replay_curation.sh non usa --run-post: gli indici li fa il passo 12.

    Giri di riparazione non usati¶

    scripts/kg/kg_postprocess.py lancia i giri di riparazione kg_repair.py … kg_repair5.py; la curatela sopra non li usa (COMMANDS.md §5).

    Se qualcosa va storto¶

    sintomo causa rimedio
    config.yaml or rebuild.env missing in <run> cartella del run incompleta copiare i due file (passo 1)
    <run>/rebuild.env does not point at the staging graph rebuild.env senza bolt://localhost:7689 correggerlo
    <file> was produced from different inputs than this run asks for configurazione, modello o artefatto precedente cambiati cancellare quel file e i successivi, o un --run-dir nuovo
    avviso PYTHONHASHSEED is …, not '42' variabile non esportata prima di lanciare Python rilanciare con PYTHONHASHSEED=42
    relation vocab not found percorso relativo del vocabolario risolto rispetto alla cartella del run (main.py:117-121) percorso assoluto nel config.yaml del run, come nel run E
    la curatela esce con 0 dopo il passo 9 o 10 proposte bilingui da leggere scrivere bilingual_excluded.json, riprendere con START_STEP
    embedding endpoint non raggiungibile al passo 12 encoder spento accendere l'encoder, START_STEP=12
    neo4j did not open bolt on 7689 within 120s lo staging non parte lo script stampa le ultime 40 righe di neo4j.log (start_neo4j_staging.sh:58-60)
