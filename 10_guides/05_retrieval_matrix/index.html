    Matrice di retrieval

    Quando serve¶

    Per confrontare il recupero solo testuale (Standard RAG: si cercano i pezzi di documento più simili alla domanda) con il recupero sul grafo (GraphRAG), misurando anche CPU, memoria e GPU durante il run. È l'unico runner che fa entrambe le cose (COMMANDS.md, sezione 8).

    Non è un runner per i numeri sul gold set

    • Costruisce la configurazione del grafo con 10 campi soltanto: la domanda, il nodo di partenza, i cinque canali del grafo, il precaricamento del modello e i due passi opzionali (run_retrieval_matrix.py:335-348). Restano spenti il canale vettoriale, le citazioni, il controllo di dominio e tutto ciò che --profile thesis_campaign accende. Il braccio Standard RAG ne imposta 2 (:409-412).
    • Non scrive query_id: la valutazione deve unire i risultati al gold per testo della domanda.

    I suoi numeri quindi non si confrontano con quelli di Lanciare una campagna. Per il gold set si usa graphrag.cli --experiment.

    Cosa tocca¶

    risorsa effetto
    grafo legge il grafo delle variabili NEO4J_* (braccio GraphRAG)
    modelli con --llm --vllm, il generatore indicato; senza --llm nessuno
    GPU i preset std_dense_* e un canale testuale dense calcolano vettori sul dispositivo di --dense-device (default auto)
    disco una cartella per run in --output-dir (default artifacts/experiments)
    tempo versione ridotta senza generazione: 6 secondi

    Le strategie¶

    Due elenchi separati: --standard-strategies e --graph-strategies. Non c'è --strategies e non c'è --models (COMMANDS.md, sezione 8).

    GraphRAG: le otto strategie di graphrag.strategies (vedi Fare una domanda); default tutte (:42).

    Standard RAG: sette preset in src/graphrag/experiments/standard_presets.py:36-56; default tutti (:58).

    preset pezzi recuperati dimensione del pezzo (caratteri) sovrapposizione ricerca
    std_topk3 3 1200 180 lessicale (tfidf)
    std_topk5 5 1200 180 lessicale
    std_wide_context 6 1800 180 lessicale
    std_fine_chunks 5 800 140 lessicale
    std_dense_topk3 3 1200 180 vettori (dense)
    std_dense_topk5 5 1200 180 vettori
    std_dense_wide 6 1800 180 vettori

    Tutti scartano i pezzi sotto 80 caratteri e mettono la fonte davanti a ogni pezzo (:30-31).

    Quali documenti usa¶

    --documents indica i file e le cartelle per il braccio Standard RAG e per il canale testuale delle strategie GraphRAG che lo usano (hybrid, text_only) (:494-512). Il default è docs README.md (:74-79), cioè la documentazione della repo, non il corpus. Per il corpus va indicato esplicitamente, per esempio --documents artifacts/corpus_circular22. --doc-patterns sceglie i file nelle cartelle (default *.pdf,*.txt,*.md,*.markdown).

    Il profilo di prestazioni¶

    --performance-profile vale auto (default), default o production_fast (:130-138). In auto, con --llm e un modello "grande", si applica production_fast, che porta --max-new-tokens a 160 se non è stato indicato; altrimenti il default è 256 (:181-222).

    "Grande" significa almeno 30 miliardi di parametri, letti dal nome del modello (llm/manager.py:76, 225-239). Misurato:

    modello miliardi letti dal nome grande? token se non indicati
    RedHatAI/Qwen3.8-27B-INT4 27 no 256
    Qwen/Qwen2.5-7B-Instruct 7 no 256
    Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 30 sì 160
    google/gemma-4-31B-it-qat-w4a16-ct 31 sì 160
    Qwen/Qwen3-32B-AWQ 32 sì 160

    Per non dipendere da questa regola: indicare sempre --max-new-tokens.

    Provare la versione ridotta¶

    Sempre prima di un run lungo. --smoke prende le prime 2 domande (--smoke-questions), i preset std_topk3,std_topk5 e le strategie default,text_plus_triples (:43, 600-622).

    I comandi di questa pagina vanno lanciati con l'ambiente graphllm attivo (conda activate graphllm, vedi Ambiente Python).

    cd /srv/projects/graphllm/experiments/graphRAGPipelineExp1
set -a; source ~/.config/graphrag/graph-db.env; set +a
CUDA_VISIBLE_DEVICES="" python scripts/runners/run_retrieval_matrix.py \
  --smoke \
  --questions-file artifacts/experiments/questions_smoke.txt \
  --documents docs/ README.md \
  --runs-per-strategy 1 \
  --output-dir artifacts/experiments \
  --experiment-tag retrieval_matrix_smoke

    Il run completo¶

    Ricetta di COMMANDS.md (sezione 8), con generatore:

    Senza --vllm-base-url il runner usa http://localhost:8000/v1 (run_retrieval_matrix.py:125).

    python scripts/runners/run_retrieval_matrix.py \
  --llm --vllm \
  --vllm-base-url http://localhost:8001/v1 \
  --model-id RedHatAI/Qwen3.8-27B-INT4 \
  --questions-file evaluation/fixtures/questions_circular_v1.txt \
  --graph-strategies "default,text_plus_triples,subgraph_2hop" \
  --runs-per-strategy 1 \
  --experiment-tag strategy_comparison

    questions_circular_v1.txt ha 20 righe (wc -l): domande sui documenti della raccolta. Il messaggio del commit 1b1c603 riporta che sulle sue prime tre righe la matrice risponde a tutte.

    Misurato sulle prime 3 righe di questions_matrix_long.txt (111 righe; le prime sono domande sul film The Matrix, estranee alla raccolta), con uscita in una cartella temporanea: uscita 0 in 307 s, 10 strategie (7 standard e le 3 del grafo); tutte le risposte dicono che l'informazione manca (insufficient_rate=100.0% in ogni strategia), quindi quel file non misura nulla sulla raccolta. Solo un lato del confronto: --skip-standard o --skip-graph (non entrambi).

    Formato delle domande¶

    Più povero di quello del CLI (:262-333):

    • file di testo: una domanda per riga;
    • .json: una lista di stringhe o di oggetti con question, oppure un oggetto con una lista questions. Le ripetizioni (senza distinguere maiuscole) vengono tolte.

    Il JSON del gold ({"queries": [...]}) non è accettato: il runner cerca la chiave questions, trova una lista vuota e si ferma con Questions JSON is empty (:262-303). Misurato chiamando _load_questions_from_json su evaluation/gold/gold_circular_v1.json, che ha le chiavi _meta e queries. Per le domande del gold c'è evaluation/fixtures/questions_gold_circular_30_en.txt (30 righe).

    Cosa viene salvato¶

    In <output-dir>/<data>_<ora>_<tag>/, tag di default retrieval_matrix o retrieval_matrix_smoke (:677-678):

    file contenuto
    results.jsonl, results.csv come per le campagne, con metadata.framework = standard_rag o graph_rag e, per Standard RAG, preset, pezzi indicizzati e documenti
    summary.txt, summary.json riepilogo per strategia; status completed o failed, con l'errore; profilo di prestazioni chiesto e applicato
    config.json argomenti, configurazione di ogni strategia GraphRAG, preset Standard RAG
    resource_samples.jsonl, resource_summary.json telemetria, se attiva (default sì; --no-monitor-resources la spegne; intervallo --resource-sample-interval, default 1 s)

    A differenza del CLI, se il run fallisce a metà i risultati parziali vengono scritti comunque, con status: failed, e poi l'errore viene rilanciato (:667-671, 748, 798-799).

    La telemetria GPU misura la scheda intera

    Il monitor legge nvidia-smi --query-gpu=…,memory.used,… (resource_monitor.py:294): memoria e utilizzo di tutta la scheda, non del solo run. Nell'esempio sopra il run girava con CUDA_VISIBLE_DEVICES="", quindi non usava la GPU, e la GPU 0 risultava comunque a 27.165 MB; con il generatore acceso anche la memoria del server vLLM entra nel conto. Per attribuire la memoria a un run serve sottrarre lo stato prima del run.

    Confrontare un profilo di prestazioni (A/B)¶

    scripts/runners/run_ab_fast_profile.py lancia run_retrieval_matrix.py due volte sulle stesse domande, con il profilo di default e con production_fast, e riporta la differenza di latenza, quanto si somigliano le risposte e, se c'è un CSV di gold, F1 sui token ed exact match (docstring, run_ab_fast_profile.py:1-7). Il file di domande predefinito del runner è evaluation/fixtures/questions_circular_v1.txt (run_ab_fast_profile.py:497). Ricetta di COMMANDS.md:

    python scripts/runners/run_ab_fast_profile.py \
  --model-id RedHatAI/Qwen3.8-27B-INT4 \
  --vllm --vllm-base-url http://localhost:8001/v1 \
  --questions-file evaluation/fixtures/questions_circular_v1.txt \
  --questions-count 10 \
  --graph-strategies default \
  --output-dir artifacts/experiments \
  --report-dir artifacts/evaluation

    sintomo causa rimedio
    unrecognized arguments: --strategies il runner usa due elenchi separati --graph-strategies / --standard-strategies
    Questions JSON is empty con un gold .json formato del gold non supportato usare un file di testo, una domanda per riga
    Unknown standard strategies: … nome di preset sbagliato uno dei sette della tabella
    Cannot skip both standard and graph matrices --skip-standard e --skip-graph insieme toglierne uno
    risposte corte o troncate con un modello da 30B in su profilo production_fast: 160 token indicare --max-new-tokens
    la strategia hybrid cita la documentazione della repo --documents lasciato al default --documents <cartella del corpus>
